# 要求仕様 (requirements.md)

## 概要
Obsidian のデスクトップ版において、アクティブなノートを CSS スタイルと画像（Data URI）を含んだ単一の HTML ファイルとしてエクスポートする機能を提供します。
このプラグインは、Obsidian 内部のレンダリング結果を忠実に再現し、外部のブラウザでオフライン閲覧可能な成果物を生成します。

## 前提条件
- ユーザーが Obsidian デスクトップ版（Windows/macOS/Linux）を使用していること。
- エクスポート対象のノートがアクティブ（表示中）であること。
- 参照される画像ファイルが Obsidian の Vault 内に存在すること。

## 制約条件
- エクスポート形式は単一の HTML (`.html`) とする。
- モバイル版 Obsidian はサポート対象外とする。
- 動的なコンテンツ（Dataview 等）は、レンダリング時点の静的な状態で出力される。

## 要件

### 要件カテゴリ1: エクスポート操作
- 要件 1-1: エクスポートの実行
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、現在開いているノートを即座に単一の HTML として書き出したい。なぜなら、フォルダ構造を気にせず他者に共有したいからだ。
    - 受け入れ基準
        - ユーザーがコマンドパレットから「Export to Single HTML」を選択したとき、システムは現在のアクティブなノートを対象にエクスポート処理を開始しなければならない。
- 要件 1-2: 保存先の指定
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、書き出すファイルの保存場所を自分で選びたい。
    - 受け入れ基準
        - エクスポートの準備が完了したとき、システムは OS 標準の保存ダイアログを表示し、ユーザーに保存先を選択させなければならない。デフォルトの拡張子は `.html` とすること。

### 要件カテゴリ2: コンテンツの再現
- 要件 2-1: WYSIWYG レンダリング
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、エクスポートされたファイルが Obsidian で見ている時と同じ見た目（数式や図解を含む）であってほしい。
    - 受け入れ基準
        - システムが Markdown を HTML に変換するとき、システムは Obsidian 標準の `MarkdownRenderer` を使用して数式（MathJax）や図解（Mermaid）を処理しなければならない。
- 要件 2-2: スタイルの適用
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、自分が設定したテーマや CSS スニペットが反映された状態で共有したい。
    - 受け入れ基準
        - システムが HTML を生成するとき、システムは現在のアクティブなテーマの CSS と有効化されている CSS スニペットを HTML に埋め込まなければならない。
- 要件 2-3: ノートタイトルの表示
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、エクスポートされた HTML の冒頭にノートのタイトルが表示されてほしい。
    - 受け入れ基準
        - システムは HTML コンテンツの最上部に、元の Obsidian ノートのファイル名を `<h1>` タグで挿入しなければならない。

### 要件カテゴリ3: リソースの埋め込み
- 要件 3-1: 画像・リソースの埋め込み (Data URI 化)
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、画像（ローカルも外部URLも）やフォントが欠落することなく、完全にオフラインで閲覧できる 1 つのファイルとして共有したい。
    - 受け入れ基準
        - ノート内にローカル画像へのリンクが存在するとき、システムは画像をバイナリとして読み込み、Base64 エンコードされた Data URI として HTML の `<img>` タグの `src` 属性に直接埋め込まなければならない。
        - ノート内に外部 URL (`http://` または `https://`) の画像リンクが存在するとき、システムはその画像をダウンロードし、Data URI として HTML 内に直接埋め込まなければならない。ダウンロードに失敗した場合はスキップし、元の URL を維持すること。
        - **強化**: CSS 内の `url()` で参照されている背景画像やフォントも同様にダウンロードし、Data URI に置換しなければならない。
- 要件 3-2: 単一 HTML フォーマットの生成
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、生成されたファイルがブラウザで正しく表示されることを期待する。
    - 受け入れ基準
        - システムがファイルを保存するとき、システムは HTML、CSS、および埋め込まれた画像を統合した自己完結型の HTML 文字列を構築しなければならない。
- 要件 3-3: YouTube 埋め込みのサムネイル変換
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、ノートに貼り付けた YouTube 動画も、オフライン（HTML単体）で見られる状態で残しておきたい。
    - 受け入れ基準
        - システムは HTML 内に YouTube の埋め込み（`<iframe>` 等、または `saved_resource.html` 経由の中間リンク）を検出したとき、その動画のサムネイル画像を自動的に取得（ダウンロード）し、Data URI として埋め込まなければならない。
        - **サムネイル取得の際、高解像度版 (`maxresdefault.jpg`) が取得できない場合は、標準高画質版 (`hqdefault.jpg`) 等をフォールバックとして試行しなければならない。**
        - 埋め込まれたサムネイル画像には、クリック時に元の YouTube 動画 URL を新しいタブで開くリンク (`<a>` タグ) を付与しなければならない。また、YouTube 公式風の再生ボタンオーバーレイを表示し、視認性を向上させなければならない。

### 要件カテゴリ4: ユーザー体験の向上
- 要件 4-1: エクスポート後の自動ブラウザ起動 (オプション)
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、エクスポートが完了したらすぐにブラウザで内容を確認したい。
    - 受け入れ基準
        - ユーザーが設定で有効にした場合、システムはファイルの保存完了後、OS 標準のデフォルトブラウザで生成されたファイルを自動的に開かなければならない。
- 要件 4-2: 画像のズーム表示 (オプション)
    - ユーザーストーリー
        - 私は Obsidian ユーザーとして、エクスポートされた HTML 内の画像をクリックして、オリジナルサイズの画像を表示したい。
    - 受け入れ基準
        - ユーザーが設定で有効にした場合、システムは HTML 内の画像を `<a>` タグでラップし、ユーザーが画像をクリックした際、ブラウザの別タブ (`_blank`) で画像単体（Data URI）が表示されるようにしなければならない (参照: ADR-0001)。
        - **モダンブラウザにおける `data:` URL へのトップフレーム遷移制限を回避するため、システムは JavaScript を注入し、`window.open()` と `document.write()` を用いて動的に画像を表示する仕組みを提供しなければならない。**

## 設定項目一覧

| 設定名 (UI) | 内部キー | デフォルト | 説明 |
| :--- | :--- | :--- | :--- |
| Rendering delay (ms) | `renderDelay` | 500 | レンダリング待機時間 |
| Include note title | `includeTitle` | false | タイトル H1 挿入 |
| Open after export | `openAfterExport` | false | 完了後にブラウザ起動 |
| Enable image zoom (open in new tab) | `enableImageZoom` | true | 別タブでの画像拡大表示 |
